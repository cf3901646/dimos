# Share pose-target IK through a common task base

Cartesian control and Quest teleoperation are sibling control tasks over a shared pose-target IK base, rather than Quest teleoperation subclassing the single-end-effector Cartesian task. The base owns model setup, IK solving, seed and joint mapping, output construction, and common validation; each leaf owns its distinct command and activation semantics. It is configured by one `RobotModelConfig`, an explicit controlled-joint set, and one or more named end-effector frame bindings, rather than parser-specific model paths, end-effector joint indices, or planning groups, and caches its kinematic context locally for the control loop. A Quest task supports a collection of exactly one or two operator-hand bindings through configuration, so single-arm and bimanual teleoperation do not require separate task subclasses. Each binding identifies a unique operator hand and target frame and may include that hand's gripper joint and calibration. The Quest leaf owns controller engagement, captured controller and robot reference poses, relative-to-absolute target mapping, and gripper input. In bimanual mode it captures and clears both hands' reference state atomically under the all-or-nothing engagement rule. The control coordinator only routes task inputs and arbitrates joint commands; it does not interpret kinematic or planning-group concepts. The initial control implementation composes the concrete Pink backend directly and shares its internal solving machinery with planning. Pink exposes an explicit one-step frame-target operation for a bounded control tick, while planning privately translates planning groups into frame targets and repeats the same internal step to convergence. A generic control-solver interface will be extracted only when another control backend is needed.

The first end-to-end product is an OpenArm Quest teleoperation blueprint containing one bimanual task, the existing single bimanual `RobotModelConfig`, and explicit in-memory whole-body hardware by default. Both Quest controller pose streams feed that one task through distinct coordinator inputs, and the shared button stream supplies the atomic two-hand deadman and both gripper values. The task solves the left and right grasp-frame targets together in one Pink step and emits one joint command covering both arms and grippers. Physical OpenArm hardware must be selected explicitly rather than being the default of this safety-sensitive blueprint.
